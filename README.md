# OTA CMS 自动化（Playwright）

独立项目：用 Playwright 驱动真实浏览器，自动完成 `cms.intsmarthub.com` 上的 OTA 升级规则
创建工作流（导入已生成的 Excel → 创建规则 → 回收 Rule ID → 逐条上线）。

> 本项目与 `ota_v4`（生成 Excel 的 Web 工具）**完全独立**。两者的衔接点只有一个：
> ota_v4 生成的 `.xlsx` 文件，作为本项目导入 CMS 的输入。

## 为什么是 Playwright（UI 自动化），不是 API

目标 CMS **没有可用的后端 API**，导入/创建规则/上线全是网页 GUI 操作。所以用 Playwright
模拟真实用户点击、填表、上传文件。

## 现状

脚手架阶段。自动化脚本**尚未实现**，因为它需要先确定 CMS 的：
1. 登录方式（账号密码 / SSO / 验证码）——决定全自动还是半自动。
2. 「导入 Excel → 创建规则」的完整点击步骤。
3. 每一步的页面元素（id / name / 文本 / 截图）。

## 安全与边界（重要）

- 凭据**绝不写死在代码里**：通过环境变量或运行时输入提供（见 `config/.env.example`）。
- 「上线」是高影响操作：脚本在上线前**暂停并等待人工确认 Rule ID**，不做无人值守的直接发布。
- 每一步自动**截图**存到 `artifacts/`，便于核对和排错。
- 请确认自动化该内部系统符合公司规范。

## 计划（分阶段）

- **M1**：登录 + 打开 OTA 导入页（打通会话，验证能进到目标页面）。
- **M2**：导入 Excel + 填规则名 + 创建 + 从页面抓回 Rule ID。
- **M3**：逐条「上线」，上线前人工确认。
- **M4**：DASS 数据填报（另一个网站）。

## 目录结构

```
ota_cms_automation/
  automation/     # Playwright 脚本（登录 / 导入 / 上线）
  config/         # .env.example、选择器配置
  artifacts/      # 运行时截图、日志、回收的 Rule ID
  requirements.txt
```

## 待你提供的信息（启动 M1 的前提）

1. CMS 登录方式：账号密码？SSO？验证码？
2. 登录后到「OTA 导入/创建规则」页的点击路径。
3. 导入/创建/上线各步的按钮与输入框（截图或 F12 元素信息）。
4. 创建成功后 Rule ID 显示在哪里（弹窗 / 列表列）。
